There are several opportunities to refactor the code to improve readability, reduce duplication, and maintain consistency without changing its behavior.

### Refactoring opportunities

1. **Extract common test objects:** Reuse the existing `SIMPLE_TRUE` and `SIMPLE_FALSE` instances instead of repeatedly creating equivalent `SimpleClass` objects.
2. **Introduce a helper method:** Create a helper method for constructing `DiffResult` instances to reduce repetitive constructor calls.
3. **Improve naming consistency:** Replace generic variable names such as `list` with descriptive names such as `diffResult`.
4. **Simplify test assertions:** Use consistent formatting and avoid unnecessary intermediate variables where doing so improves readability.
5. **Use generic types consistently:** Replace the raw `DiffResult` declaration in `testLeftAndRightGetters()` with `DiffResult<SimpleClass>`.

### Summary of improvements

| Area | Improvement |
| --- | --- |
| Object creation | Reuses shared test instances |
| Code duplication | Introduces `createDiffResult()` |
| Naming | Uses descriptive `diffResult` variables |
| Type safety | Eliminates raw `DiffResult` usage |
| Readability | Improves formatting and consistency |
| Maintainability | Centralizes common test setup |

**Important:** These changes preserve the intended test behavior. The original test coverage, including null validation, immutability, iteration, and string formatting, is retained.

The refactoring is primarily aimed at making the test class easier to maintain and understand rather than changing its functionality.
